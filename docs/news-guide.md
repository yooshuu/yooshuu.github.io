# 소식 글 작성 기준

월·수·금에 올립니다.

## 다루는 내용

분야:

- AI 및 AI 에이전트
- Python, Java 등 프로그래밍 언어
- AWS 등 클라우드와 Kubernetes
- 빅데이터 및 데이터 엔지니어링
- 소프트웨어 보안

종류:

- 새 모델, 기능, 오픈소스 공개
- 새 버전에서 기술적으로 달라진 점
- API 변경과 지원 종료
- 보안 취약점과 대응 방법

다섯 분야를 같은 비중으로 보고, 특정 분야를 우선하지 않습니다.

## 기준 자료

- 기업과 프로젝트의 공식 블로그, 보도자료, 릴리스 노트, 변경 이력, 기술 문서만 사용합니다.
- 뉴스 기사, 개인 블로그, SNS, 커뮤니티 글은 소식을 찾을 때도, 내용을 확인할 때도 사용하지 않습니다.
- 공식 원문을 직접 읽지 못한 소식은 다루지 않습니다.

## 다루지 않는 내용

- 공식 자료로 확인되지 않는 소문과 유출 정보
- 내용 없이 홍보만 있는 발표
- 요금제, 가격, 약관처럼 기술 변화가 아닌 소식

## 쓸 때 지킬 점

- 글 하나에 가장 중요한 소식 하나만 약 3,000자로 씁니다.
- 순서는 도입, 한눈에 보기, 왜?, 본문 소제목, 참고 자료입니다.
- 본문 소제목은 3~4개로 하고, 이름과 역할은 주제에 맞게 정합니다.
- 본문 소제목 앞에는 `1.`, `2.`처럼 번호를 붙입니다. 참고 자료에는 붙이지 않습니다.
- 태그는 Tag List에 자동으로 묶여 표시됩니다. 같은 대상은 이미 쓴 태그 표기를 그대로 씁니다(예: `AWS`, `Iceberg`).
- 이미 된 것, 예정인 것, 베타인 것을 구분합니다.
- 업데이트라면 이전과 무엇이 달라졌는지 씁니다.
- 출처를 밝힐 때는 "AWS에 따르면 ~합니다"처럼 출처를 문장 앞에 둡니다. "~할 수 있었다고 설명합니다"처럼 추측과 인용을 겹치지 않습니다.
- 문장마다 주어가 분명하게 드러나도록 씁니다.

## 술술 읽히게 쓰기

- 말투는 "~합니다"체로 씁니다.
- 흐름은 접속사보다 내용의 순서로 잇습니다. 앞 문장의 단어를 이어받아("이 기능은", "이 세 단계는") 자연스럽게 연결합니다.
- 접속사("그래서", "결국", "또", "이때" 등)는 흐름이 실제로 바뀌는 곳에만 쓰고, 한 문단에 두 개 이상 넣지 않습니다. 글 전체에서 서너 개면 충분합니다.
- 소제목마다 "그렇다면 ~할까요?" 같은 같은 형식의 질문으로 시작하지 않습니다. 첫 문장은 바로 내용으로 들어갑니다.
- 같은 어미("~했습니다" 등)가 연달아 이어지면 문장을 합치거나 끝맺음을 바꿉니다.
- 괄호 안에 여러 항목을 나열하지 않고 목록이나 표로 풀어 씁니다.
- "왜?" 코너에서 한 말을 본문에서 그대로 되풀이하지 않습니다.
- 큰 소식이 없는 날에는 억지로 올리지 않습니다.

## "왜?" 코너

염소 캐릭터가 묻고 답하는 코너입니다.

- 질문은 앞 문단에 이어지는 말이 아니라 그 자체로 읽히는 독립된 질문으로 씁니다. "그런데", "그럼" 같은 연결어를 붙이지 않습니다.

- 공식 자료에 나온 변경 이유를 쉽게 풀어 씁니다.
- 이유는 없지만 기술 설명이 있으면, 그 기술이 왜 쓰이는지를 공식 문서를 바탕으로 씁니다.
- 공식 자료에 근거가 없으면 코너를 빼고, 추측으로 채우지 않습니다.

## 글 쓰기

1. `_template-news.md`를 복사해 `_posts/YYYY-MM-DD-제목.md`로 저장합니다.
2. 제목, 날짜, 요약을 바꾸고 주제에 맞는 소제목으로 본문을 쓴 뒤 참고 자료를 답니다.
3. `main`에 push하면 자동으로 배포됩니다.
