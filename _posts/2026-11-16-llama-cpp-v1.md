llama.cpp는 양자화와 하드웨어별 최적화로 노트북부터 서버까지 여러 기기에서 LLM을 돌리는 C/C++ 오픈소스입니다. ggml-org는 2026년 11월 13일 **llama.cpp v1.0.0**과 그 바탕인 텐서 라이브러리 **ggml v1.0.0**을 함께 공개했습니다. 첫 커밋 뒤 약 3년 반 만의 1.0이며, 이번 발표의 중심은 새 기능보다 라이브러리 API를 언제 깨뜨릴지 밖에서 알 수 있게 하는 버전 규칙입니다.

## 1. 1.0이 된 두 라이브러리와 버전 규칙

이번에 v1.0.0이 된 대상은 실행 프로그램이 아니라 라이브러리입니다.

| 프로젝트 | 라이브러리 | 공개 헤더 | 직전 버전 |
| --- | --- | --- | --- |
| llama.cpp | `libllama` | `llama.cpp/include/` | v0.9.0 |
| ggml | `libggml` | `ggml/include/` | v0.29.0 |

ggml-org는 모든 프로젝트에 유의적 버전(semantic versioning)을 적용합니다. 발표 글이 밝힌 규칙은 세 가지입니다.

- **MAJOR:** `include` 폴더에 있는 공개 C API를 깨는 변경
- **MINOR:** 하위 호환되는 기능, 백엔드 업데이트, 새 모델 지원, API 추가
- **PATCH:** API가 바뀌지 않는 버그 수정

야간 빌드는 지금처럼 `b12359` 같은 `bNUM` 태그로 계속 나옵니다. 버전 정책을 정리한 ggml 토론 글에 따르면 정식 릴리스는 `vX.Y.Z` 태그를 달고, 릴리스마다 대응하는 야간 빌드를 가리킵니다. 각 릴리스에는 그 야간 빌드 태그를 적은 `nightly-tag.txt` 파일도 들어갑니다. 정식 릴리스 태그는 llama.cpp 안에 든 ggml 사본이 릴리스된 ggml과 같을 때만 만듭니다. 이 조건 덕분에 릴리스 태그로 빌드한 프로그램을 시스템에 설치된 ggml과 연결해도 호환됩니다.

## 2. 지워지고 옮겨진 API

llama.cpp 릴리스 노트는 v1.0.0이 "폐기 예정이던 공개 API를 제거한다"고 밝힙니다. 기존 코드를 v1.0.0으로 올릴 때 확인할 변경은 다음과 같습니다.

- `llama.h`에서 `llama_set_warmup`, 폐기 예정 함수 35개, `defrag_thold`와 명령줄 옵션 `--defrag-thold`를 지웠습니다.
- 추측 디코딩에 쓰는 NextN API를 `llama-ext.h`에서 공개 헤더인 `llama.h`로 옮겼습니다.
- `llama_set_embd_state_src`의 이름이 `llama_set_ctx_state_src`로 바뀌었습니다.
- ggml v1.0.0도 폐기 예정 공개 API와 예전 `DIAG_MASK` 연산을 지웠습니다.

릴리스 노트에 "Breaking changes"라는 별도 항목은 없고, 이 내용은 "API changes" 항목에 들어 있습니다. 발표 글과 릴리스 노트 어디에도 따로 정리한 이전 안내서는 없습니다.

## 3. 새로 들어간 기능

새 기능은 추론 속도와 메모리 사용, 다룰 수 있는 모델 범위에 걸쳐 있습니다.

| 영역 | 내용 |
| --- | --- |
| KV 캐시 | `-ctk/-ctv f8_e4m3` 옵션으로 OCP FP8 형식 KV 캐시를 씁니다. 텐서별 고정 스케일을 선택해 줄 수 있습니다. |
| MoE | 호스트 메모리에 전문가 가중치를 두는 MoE 캐시가 생겼고, `llama_context_params`에 `moe_cache_size`와 `moe_cache_cpu_share`가 추가되었습니다. |
| 모델 | 텍스트 아키텍처 Kimi-K3.1-Pro, Ripple, xing4_0과 음성 합성 모델 drama-3, 비전 모델 MageVL-Cowork와 Kimi-K3.1을 지원합니다. |
| 서버 | OpenAI 호환 `/v1/audio/speech` 엔드포인트가 생겼고, `/tts`에 `temperature` 옵션이 붙었습니다. |
| 웹 UI | 채팅 그룹과 마크다운 편집기가 있는 새 화면으로 바뀌었습니다. |

llama-server의 보안도 손봤습니다. 릴리스 노트는 `--cors-origins`, DNS 리바인딩, CORS 프록시의 SSRF, 자식 인스턴스 접근 문제를 고쳤다고 적고 있으며, 커밋 목록에는 미디어 URL의 SSRF 수정도 있습니다. MCP 도구 호출을 중간에 취소하는 기능도 들어갔습니다.

ggml v1.0.0은 백엔드별 개선을 담았습니다. CUDA는 OCP FP8을 지원하고, Metal은 MoE 라우팅을 합쳐 처리하며, Vulkan에는 Intel용 FlashAttention 프리필 커널이 생겼습니다. Hexagon은 Q5_0·Q5_1 형식과 conv_3d를 지원하게 되었습니다.

## 4. 배포 경로와 개발 방식

발표 글에 따르면 llama.cpp는 다음 경로로 받을 수 있습니다.

- GitHub 릴리스 파일: Linux, macOS, Windows, Android, iOS
- Docker, Debian: Linux
- Homebrew: macOS, Linux
- conda-forge: Windows, macOS, Linux
- MacPorts: macOS
- Winget: Windows
- XCFramework: iOS, macOS

ggml은 백엔드마다 동적 라이브러리로 빌드해 실행 중에 골라 불러올 수 있게 설계되었고, llama.cpp는 150개가 넘는 아키텍처 변형과 주요 추측 디코딩 방식을 지원합니다. ggml-org는 `master`에 들어가는 모든 변경을 CI로 검증하도록 투자를 늘리고 있으며, Hugging Face Buckets와 HF Jobs로 CI 용량을 늘렸습니다. NVIDIA, AMD, Qualcomm, Arm, IBM, Intel이 하드웨어를 지원하고, 주요 플랫폼에 자체 호스팅 러너를 더 붙이는 중입니다.
